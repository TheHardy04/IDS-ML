\section{Business Scope and Problem Formalization}

\subsection{Business Case}
% "Define precisely the problem you want to solve... and how this is directly linked to your field of specialization." [cite: 165]
% Mention why this problem is interesting/relevant.
The rapid proliferation of the Internet of Things (projected to reach 125 billion interconnected IoT devices by 2030 \cite{saadouni2025identification}) in sectors such as healthcare, smart cities, and industry has created a vast new attack surface for cybercriminals. As highlighted by recent research, these devices are frequently targeted by varied and sophisticated attacks, such as Distributed Denial of Service (DDoS)\cite{khan2022internet} and SSH Brute-Force exploits \cite{fahrnberger2022realtime}, often due to weak default security configurations.

While detecting an anomaly is a critical first step, a robust security system must also identify the specific type of attack to automate the correct response. For instance, a DDoS attack requires traffic rate-limiting, whereas an SSH Brute-Force attack requires blocking specific 
IP addresses or locking credentials.

Consequently, the business objective of this project is to build a robust, multi-class Intrusion Detection System (IDS). Unlike the original research which focused on lightweight deployment for resource-constrained devices, our project pivots to prioritize model robustness and granular identification. The goal is not merely to detect intruders, but to accurately categorize network traffic into specific normal profiles and distinct attack classes, ensuring precise and targeted mitigation strategies.

\subsection{Problem Formalization}
% Define the objective formally (e.g., "We aim to maximize F1-score for binary classification of...").
% Mention the formal methods used[cite: 316].

We formalize this project as a Multiclass Classification problem. Unlike simple binary detection, our model must distinguish between benign behaviors and specific attack signatures to ensure the security of the IoT infrastructure.

\begin{itemize}
    \item \textbf{Input (X)}: Network traffic features derived from the RT-IoT2022 dataset\cite{sharmila2023quantized}, such as packet inter-arrival times, flow duration, and flag counts.
    \item \textbf{Output (Y)}: A categorical label indicating one of several classes: 
    \begin{itemize}
        \item \textbf{Normal Traffic :} Traffic from specific devices including ThingSpeak-LED, MQTT-Temp, Wipro-Bulb, and Amazon-Alexa.
        \item \textbf{Attack Traffic :} Including DDoS, SSH Brute-Force, SYN Flood, UDP Flood, and Scan attacks.
    \end{itemize}
\end{itemize}

Our objective is to maximize the overall Macro-Averaged F1-Score. This metric is crucial because it ensures the model performs well across all classes, preventing the "robustness" score from being skewed by the most frequent traffic type (class imbalance).

\section{Data Description and Exploration}

\subsection{Dataset Source}
% Describe the source (Kaggle, UCI, etc.) and reliability[cite: 167].

The dataset used in this project is the RT-IoT2022 (Real-Time Internet of Things 2022) dataset, developed by Sharmila and Nagapadma (2023) \cite{sharmila2023quantized}. Unlike many synthetic datasets, RT-IoT2022 was generated using a physical testbed infrastructure comprising real-time IoT devices, ensuring the network traffic reflects authentic behavior rather than simulated patterns.

The data collection infrastructure consisted of two distinct networks connected via a router: a victim network of IoT devices and an attacker network. The specific IoT devices used to generate benign (normal) traffic include:

\begin{itemize}
    \item \textbf{ThingSpeak-LED}: An IoT LED light controlled via the ThingSpeak platform.
    \item \textbf{MQTT-Temp}: A Raspberry Pi device transmitting temperature sensor data to a Mosquitto Broker via the MQTT protocol.
    \item \textbf{Wipro-Bulb}: A smart home integrated solution (NS9400 9-Watt B22) controlled via WiFi.
    \item \textbf{Amazon-Alexa}: An Echo Dot device communicating with cloud-based voice services.
\end{itemize}

Raw network traffic was captured using Wireshark\footnote{\url{https://www.wireshark.org/}} and processed using the CICFlowmeter\footnote{\url{https://github.com/ahlashkari/CICFlowMeter}} tool. This process converted raw packet data into bidirectional flow-based features (e.g., Flow Duration, Packet Inter-arrival Time, Flag Counts). To prevent model bias, specific identifiers such as source/destination IP addresses and Flow IDs were removed during preprocessing.

\subsection{Exploratory Data Analysis (EDA)} \label{sec:eda}
% Include graphics/figures here.
% Discuss:
% - Missing values [cite: 321]
% - Imbalanced data [cite: 322]
% - Outliers [cite: 323]

To ensure the data was suitable for machine learning applications, we examined several key components, starting with the feature structure. It was observed that the dataset features are not raw packet data but rather pre-computed statistical aggregations (including mean, standard deviation, and max/min values) generated by the extraction tool. Consequently, our analysis focused on understanding how these aggregated metrics, such as \texttt{flow\_duration}, \texttt{idle.std}, or \texttt{packet\_inter\_arrival\_time}, differentiate between normal and anomalous behaviors.

A systematic integrity check was conducted, confirming that the dataset is pristine and fully populated, with no missing values or null entries. As a result, no imputation or data cleaning procedures were required, allowing us to proceed directly to distribution analysis.

The most critical finding during this phase was the significant Class Imbalance within the target labels. Our distribution analysis revealed a stark disparity across all target labels. This imbalance is a crucial characteristic that directly influenced our modeling strategy, necessitating the use of weighted evaluation metrics (such as the Macro-Averaged F1-Score) and stratified splitting techniques to prevent model bias.

Finally, correlations between features were examined to identify redundant variables or multicollinearity common in flow-based datasets, while potential outliers were reviewed to distinguish between measurement errors and genuine anomalous network behaviors relevant to cybersecurity analysis.

\section{Methodology}

\subsection{Preprocessing}
% Discuss encoding, scaling, duplicate removal[cite: 153].
As mentioned in \ref{sec:eda}, the dataset was already preprocessed. It was cleaned and required no missing value imputation or duplicate removal. However, feature scaling and label encoding were performed using \texttt{StandardScaler}, \texttt{LabelEncoder} and \texttt{OneHotEncoder} from the sklearn library. This ensured that all features were on a comparable scale, which is particularly important for distance-based algorithms.

\subsection{Algorithm Description}
% Briefly describe the models chosen (Standard vs Advanced)[cite: 317].
% Mention the "advanced version" or "algorithm outside scope" here[cite: 307].

For the algorithm implementation, we selected a combination of standard   models presented during our Machine Learning course at ESILV and advanced machine learning models to address the multiclass classification problem effectively.

\subsubsection{Logistic Regression Description}

First, we implemented Logistic Regression, a widely used statistical model for binary and multiclass classification tasks. Logistic Regression estimates the probability of a data point belonging to a particular class using the logistic function. It is particularly effective for linearly separable data and provides interpretable coefficients that indicate the influence of each feature on the predicted outcome.

\subsubsection{Random Forest}

We also employed Random Forest, an ensemble learning method that constructs multiple decision trees during training and outputs the mode of the classes for classification tasks. Random Forests are known for their robustness to overfitting, ability to handle high-dimensional data, and effectiveness in capturing complex interactions between features.

\subsubsection{Logistic Regression with PCA}

As our dataset contains a large number of features, we applied Principal Component Analysis (PCA) as a dimensionality reduction technique before training the Logistic Regression model. PCA transforms the original features into a new set of 10 uncorrelated variables (principal components) that capture the maximum variance in the data. This helps to reduce noise and improve model performance by focusing on the most informative aspects of the dataset.

\subsubsection{Grid Search}

To optimize the hyperparameters of our models, we utilized Grid Search, a systematic approach to exhaustively search through a specified subset of hyperparameters. By evaluating model performance across different combinations of hyperparameters using cross-validation, Grid Search helps identify the optimal settings that yield the best performance on the validation set. This method is particularly useful for tuning models like Logistic Regression and Random Forest, where parameters such as regularization strength and the number of trees can significantly impact results.

\subsubsection{WDRO}

Wasserstein Distributionally Robust Optimization (WDRO) is a mathematical framework that can provide robustness to data shifts in machine learning models. Distributionally Robust Optimization (DRO) introduces a solution by considering the worst expectation of the cost function when the probability distribution belongs to a neighborhood around the empirical distribution. 

A recent push has been made towards wider neighborhoods notions for DRO led by the WDRO formulation. Its ambiguity set relies on the Wasserstein optimal transport cost. We consider an ambiguity set as a "ball" of plausible distributions centered around a nominal distribution (e.g., the empirical distribution of training data), where the radius of the ball is defined by the Wasserstein distance. WDRO seeks to minimize the worst-case risk over all distributions within this Wasserstein ball, ensuring that the model performs well even if the true distribution differs from the training data within the specified radius. \cite{mohajerin2018data,gao2024wasserstein, kuhn2019wasserstein}

\subsubsection{Projected Gradient Descent (PGD) Adversarial Training}

To get a robust model we looked at adversarial attacks and particularly the Projected Gradient Descent attack proposed by Madry et al \cite{madry2017towards}.

The Projected Gradient Descent attack is an iterative method in which, after each iteration, the perturbation is projected on an lp-ball of specified radius (in addition to clipping the values of the adversarial sample so that it lies in the permitted data range).

Unfortunately, due to errors in our notebook we did not manage to correctly implement this attack and thus evaluate our model through adversarial attacks.

\subsubsection{Grid Search}

To optimize model performance, we initially considered an exhaustive \texttt{GridSearchCV}. However, given the significant computational cost associated with searching high-dimensional parameter spaces on a large dataset, we adopted a more efficient optimization strategy.

First, we transitioned to \texttt{RandomizedSearchCV}, a hyperparameter tuning technique that samples a fixed number of parameter settings (\texttt{n\_iter}) from specified distributions. Unlike standard grid search, which evaluates every possible combination, randomized search allows for a broad exploration of the parameter space with significantly reduced computational overhead. To further limit training time, we narrowed the hyperparameter search space and reduced the cross-validation strategy to 3-fold validation.

We evaluated four distinct algorithms: \texttt{DecisionTreeClassifier}, \\\texttt{RandomForestClassifier}, \texttt{SVC}, and \texttt{BaggingClassifier}.

All optimized models demonstrated robust performance, achieving accuracies exceeding 96\%. Among these candidates, the \texttt{BaggingClassifier} proved to be the superior model, yielding a near-perfect accuracy of 99.8\% and an F1-score of 0.998. This suggests that the ensemble approach of bagging successfully mitigated variance while retaining high predictive power.
While the \texttt{BaggingClassifier} achieved an exceptional accuracy of 99.8\%, such near-perfect results warrant critical scrutiny regarding potential overfitting. Although Bagging is designed to reduce variance, a score this high may indicate that the model has memorized specific traffic patterns unique to the limited number of devices in our testbed, rather than learning generalizable attack signatures. In a real-world deployment with diverse IoT hardware, this performance would likely degrade.

\section{Discussion and Limitations}

\subsection{Addressing Obstacles}
Throughout the project, we encountered several challenges inherent to cybersecurity datasets and machine learning deployment.

Class Imbalance: As noted in the EDA, the dataset exhibited a significant disparity between normal traffic and specific attack classes (e.g., SSH Brute Force). To address this, we shifted our evaluation metric from simple accuracy to the Macro-Averaged F1-Score, ensuring that minority classes were not ignored. We also experimented with SMOTE (Synthetic Minority Over-sampling Technique) to artificially balance the training set. While it provided minor improvements, the high quality of the cleaned dataset meant that standard ensemble methods like Random Forest handled the imbalance relatively well without aggressive resampling.

High Dimensionality: The raw dataset contained numerous flow-based features, which increased computational cost and noise. We successfully addressed this by implementing Principal Component Analysis (PCA), reducing the feature space to 10 uncorrelated components. This not only accelerated training times for the Logistic Regression model but also helped in visualizing the data structure.

Model Robustness: A key objective was ensuring the model's reliability under noise. Standard models often fail when data drifts slightly from the training distribution. By implementing Wasserstein Distributionally Robust Optimization (WDRO), we successfully created a model that maintains performance even when subjected to Gaussian noise. Our experiments showed that a small robustness radius ($\rho=10^{-5}$) offered the best trade-off, protecting against noise without being overly conservative.

\subsection{Limitations}
Despite the strong performance metrics, our project has several limitations that must be acknowledged:

\begin{itemize}
    \item \textbf{Dataset Scope:} As mentioned, the RT-IoT2022 dataset is limited to only two major attack types (DDoS and SSH Brute-Force) and four specific IoT devices. This restricts the model's ability to generalize to other common threats like Ransomware or SQL Injection, or to different IoT hardware architectures.
    \item \textbf{Adversarial Vulnerability:} We aimed to evaluate our models against active adversarial attacks using Projected Gradient Descent (PGD). However, due to implementation errors in the attack pipeline, we could not quantify our model's resilience against intelligent adversaries who deliberately perturb inputs to evade detection.
    \item \textbf{Potential Overfitting:} The BaggingClassifier achieved a near-perfect accuracy of 99.8\%. While impressive, such a score in a controlled testbed often indicates overfitting. The model likely memorized specific traffic signatures of the four test devices rather than learning generalized attack behaviors, which would likely lead to performance degradation in a diverse, real-world network.
\end{itemize}

\section{Conclusion}

The objective of this project was to develop a robust, multi-class Intrusion Detection System (IDS) capable of securing IoT environments. Using the RT-IoT2022 dataset, we implemented and compared several architectures, ranging from interpretable Logistic Regression to complex Ensemble methods and Robust Optimization techniques.

Our results demonstrate that machine learning can effectively classify IoT network traffic with high precision. All implemented models achieved exceptional performance metrics, with F1-scores consistently exceeding 0.96. While the BaggingClassifier yielded the highest raw score (0.998), the uniformly high performance across diverse algorithms suggests a strong signal in the dataset, but also raises valid concerns regarding potential overfitting to the specific devices in our testbed.

Furthermore, our experiments with WDRO highlighted the critical distinction between accuracy and robustness. We found that while standard models perform exceptionally well on clean data, their performance degrades under noise. The WDRO framework provided a mechanism to mitigate this, though it requires careful tuning of the uncertainty radius ($\rho$) to avoid over-conservatism.

Finally, it is important to recall that the RT-IoT2022 dataset was originally designed to benchmark lightweight models for resource-constrained devices \cite{sharmila2023quantized}. While our project prioritized algorithmic robustness, the logical next step would be to apply optimization techniques—such as quantization or pruning—to our best-performing models. As demonstrated by the original authors, reducing the model size would allow our robust IDS to be deployed directly on edge hardware (e.g., Raspberry Pi) with minimal latency and power consumption.
